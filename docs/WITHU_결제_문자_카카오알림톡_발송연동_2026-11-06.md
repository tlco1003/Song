# WITHU 결제화면 · 이메일/문자/카카오 알림톡 발송 연동
작성일: 2026-11-06

## 고객 화면
- 결제정보: 이메일 입력 1개 + 휴대전화 입력 1개. 중복 이메일 확인란 제거.
- 완성곡 안내 수신 방법 선택: 이메일 / 문자 링크 / 카카오 알림톡.
- 수신 방법을 선택하고, 전용 감상 링크 발송을 위한 연락처 이용 동의를 표시한다.
- 노래 제작이 실제로 완료된 뒤 고객별 https://운영도메인/my-music.html#delivery=개인토큰 링크를 안내한다.
- 노래 제작 및 결제 검증, 고객 본인 인증, 전달권한 확인 전에는 메시지를 보내지 않는다.
- 현재 결제 버튼은 비활성화. 고객이 입력한 연락처는 아직 서버로 전송하거나 저장하지 않는다.

## 서버 진입점
- src/customer-notification-contact.mjs: 이메일, 한국 휴대전화 형식, 알림 수신 방식, 동의 검증.
- src/private-delivery-invitation.mjs: 결제/작품/수령자 검증, 난수 링크 발급과 해시 저장, 채널별 전송 호출.
- src/withu-notification-providers.mjs: 실제 REST 형태의 Resend 이메일, Bizgo LMS/카카오 알림톡 어댑터.
- src/dispatch-completed-music.mjs: 운영자 제작 완료 주문에서 알림 수단에 따라 발송기 연결.
- test/customer-notification.test.mjs: 모의 HTTP로 API 요청 형식/거절/개인 링크/결제 전 차단 확인.

## 운영 서버 비밀키 설정
아래 키들은 저장소의 .env.example 에 이름만 남겨 두었다. 실제 키는 비공개 운영 서버의 환경변수 또는 Secret Manager에 넣는다.
GitHub Pages의 자바스크립트, 프런트엔드, GitHub 커밋, 로그에 실제 키를 넣지 않는다.

| 환경변수 | 의미 |
| --- | --- |
| WITHU_PUBLIC_BASE_URL | 실제 서비스 HTTPS 기본 주소(동일 출처 호스팅). |
| RESEND_API_KEY | Resend 이메일 서비스 비밀키 |
| WITHU_FROM_EMAIL | 인증된 이메일 발신주소 |
| WITHU_BIZGO_AUTHORIZATION | 실제 Bizgo 발급 Authorization 헤더 값 |
| WITHU_BIZGO_SMS_SENDER | 문자 발신번호 등록·검증을 마친 전화번호 |
| WITHU_BIZGO_KAKAO_SENDER_KEY | 카카오 비즈니스 인증 채널의 발신 프로필 키 |
| WITHU_BIZGO_KAKAO_TEMPLATE_CODE | 승인 완료된 정보성 알림톡 템플릿 코드 |
| WITHU_BIZGO_KAKAO_TEMPLATE_TEXT | 그 승인된 템플릿의 정확한 안내 문장 |

모든 실제 키는 현재 빈칸이며, 키가 없으면 provider 요청은 발송되지 않고 오류를 반환한다.

## 문자 발송(LMS)
- Bizgo HTTP API: POST https://mars.ibapi.kr/api/comm/v1/send/omni
- 고객 개인 링크는 길어서 단문 SMS(90바이트) 대신 첨부 없는 LMS(messageFlow.mms)를 사용.
- 등록된 발신번호와 모바일 수신번호, 메시지 본문, 멱등키를 보낸다.
- Bizgo HTTP 성공 및 수신자별 발송접수 코드가 확인되어야 접수됨으로 기록.
- 실제 도착/읽음과 발송 접수는 다른 상태이며, 리포트/웹훅 연동이 운영 단계에서 필요.
- 공식 문서: https://developers.bizgo.io/api-sdk/api-reference/comm/mt

## 카카오 알림톡 발송
- 문자 발송과 동일한 Bizgo OMNI API를 쓰되, messageFlow.alimtalk 타입으로 전송.
- 고객 전화번호에 주문 이행용 정보성 메시지만 보낸다. 무작위 광고 메시지는 발송하지 않는다.
- 카카오 비즈니스 채널 인증, 발신 프로필 등록, 정보성 템플릿의 **사전 심사 승인**이 필수.
- 승인된 템플릿의 문구와 '나의 노래함' 웹링크 버튼이 실제 API 값과 일치해야 한다.
- 템플릿의 링크 버튼은 고객 전용 HTTPS 링크를 향한다. 미승인 템플릿으로 강제 발송하지 않는다.
- 현재 알림톡 실패 시 자동 문자 대체 발송은 시행하지 않는다. 사용자가 선택한 채널만 요청한다.
- 공식: https://kakaobusiness.gitbook.io/main/ad/infotalk
- 개발 규격: https://developers.bizgo.io/api-sdk/api-reference/comm/kakao-alimtalk

## 이메일 발송
- Resend API: POST https://api.resend.com/emails
- 발신 도메인 인증, 개인 링크 텍스트, 주문별 Idempotency-Key 적용.
- 발송 접수/도착 확인은 별개이며 실제 제공사 리포트/웹훅 연동 필요.
- 공식: https://resend.com/docs/api-reference/emails/send-email

## 안전한 운영 전환 조건
1. 실 PG 검증과 주문 DB 연결. 결제 전·실패한 주문은 발송하지 않는다.
2. 고객 이메일과 휴대전화 확인/동의, SMS/카카오 수신번호의 소유 검증(OTP 등) 구현.
3. 제작 완료된 원본·가사만 비공개 스토리지에 저장하고 고객에게 권한 부여.
4. DB에서 전송 토큰 해시를 저장한 다음 주문별 Outbox/멱등키를 사용하여 발송.
5. 이메일·문자·알림톡 제공사에서 정확한 키/검증된 발신자를 발급받고 승인 템플릿을 등록.
6. 실패 재시도·수신/발송 리포트·링크 만료/재발급·개인정보 삭제·전송 실패 보호 구현.
7. GitHub Pages 단독 정적 호스팅으로는 발송기나 비공개 주문 DB가 동작하지 않는다. 동일 출처의 서버 구축 필요.

현재 상태는 **사용자 화면 + 실제 API 요청 어댑터 + 코드 테스트 + 비밀키 입력 자리** 구현. 실 PG/회원/전화 OTP/메일/SMS/알림톡 발송자 계정과 주문 DB 운영 연결은 아직 완료되지 않았다.
