## 로컬에서 직접 시험하는 방법

Node.js 22 이상과 OpenSSL이 설치된 개발용 컴퓨터에서 GitHub 최신 main 코드를 받아 진행한다.

~~~bash
git clone https://github.com/tlco1003/Song.git
cd Song

export HOST=127.0.0.1
export PORT=3000
export WITHU_STAGING_ENABLED=true
export WITHU_STAGING_ADMIN_KEY="$(openssl rand -hex 32)"
export WITHU_PRIVATE_MUSIC_DIR="$(mktemp -d -t withu-private-test-XXXXXX)"

# 관리자 화면에서 사용할 키는 서버 시작 전에 이 터미널에 일회 표시
printf '%s\n' "$WITHU_STAGING_ADMIN_KEY"

npm run staging
~~~

이 키는 해당 컴퓨터 로컬 관리자 UI에만 입력한다. GitHub 커밋·공개 사이트·로그로 전송 금지.

**시험 순서:**

1. http://127.0.0.1:3000/create.html 에서 사연과 음악 장르·스타일 선택.
2. 같은 호스트의 checkout.html에서 1곡/2곡과 추가 옵션 선택 후 payment.html로 진행.
3. 로컬 payment.html에만 나타나는 가짜 결제완료 시험 링크로 이동. 또는 http://127.0.0.1:3000/_staging 직접 방문.
4. 관리자 키·시험 이메일·시험 휴대전화·채널을 입력하고 '테스트 주문 생성' 클릭.
5. '모의 결제완료로 전환'을 눌러 TEST_PAYMENT_COMPLETE_NO_CHARGE 상태로 변경.
6. 직접 제작한 MP3/M4A/WAV를 등록하고 제목·가사를 입력. 2곡 상품은 2개 파일을 각각 등록.
7. '모의 제작 완료 및 전용 링크 생성'을 누른 뒤 '모의 발송함 확인'에서 고객별 링크 열기.
8. 동일 컴퓨터의 나의 노래함에서 주문 고객 음악만 재생되는지 확인.
9. 다른 테스트 이메일로 새 주문을 만들고 접근 토큰·세션을 바꿔도 상대방의 음원을 조회할 수 없는지 검사.
10. 이미 열었던 배송 링크를 다시 사용하면 거절된다. 로컬 테스트 서버를 재시작하면 주문과 세션 상태는 사라진다.

**주의:** 이 실험은 실제 결제, 실제 이메일 도착, 실제 Suno 생성이 아니다. 공개 GitHub Pages에서는 관리자 결제완료 기능을 제공하지 않는다. 고객별 파일은 공개 docs/media가 아닌 비공개 폴더에 둔다.

## 사업용 자동화의 백엔드 연결 순서

1. 비공개 주문 드래프트: src/order-draft-preparation.mjs → src/private-draft-store.mjs. 사용자에게 1000자 스타일 프롬프트/작사 지시를 노출하지 않는다.
2. 결제 대기 주문: src/create-verified-checkout-intent.mjs. 서버 가격·연락처 동의·암호화된 초안 ID로 payment_pending DB 레코드 원자 저장.
3. 결제 승인: src/toss-payment-adapter.mjs 와 src/paid-order-pipeline.mjs. PG가 실제 확인한 주문번호, 결제키, 총액, 통화, DONE 여부가 일치해야 PAID와 제작 작업 큐를 생성.
4. 가사 제작: src/verified-fulfillment-worker.mjs 에서 **결제 후에만** 서버 비공개 작사 지시를 사용해 가사를 생성·검증하고 곡별 스타일 계획을 저장.
5. 사업용 Suno API 승인 여부 검증: 승인된 사업자 제공자와 계약이 있으면 licensed music provider로 요청; 그렇지 않으면 manual_operator 경로로 자동 전환.
6. 관리자는 src/operator-alert-channels.mjs 의 Resend 이메일 또는 Bizgo LMS로 결제 확인된 제작 요청을 받을 수 있도록 준비. 문자에는 고객의 상세 사연·비공개 프롬프트나 재생 링크를 포함하지 않음.
7. 자동/수동 제작 음원은 src/finalize-licensed-customer-delivery.mjs 의 고객별 최종 선정곡, 음질·보컬·가사·권리·스토리지 검증을 통과해야 한다.
8. 통과한 최종 파일만 src/dispatch-completed-music.mjs 로 고객 이메일/LMS/카카오 알림톡 전송. 개인 256비트 토큰 링크 발급 후 비공개 주문 DB에 해시 기록.
9. 고객은 my-music.html에서 세션 인증과 권한 확인을 통과한 자신의 곡만 재생.

**현재 이 코드는 통합 가능한 포트와 계약/테스트까지 구현된 것이다.** 실제 DB, Suno B2B, PG, 이메일 발송 서비스가 설치되지 않았으므로 키만 입력해 모든 기능이 자동으로 동작한다고 주장하지 않는다.

## 실제 메일 수신 시험 (키/도메인 연결 후)

- Resend에서 실제 발신 도메인 인증 후 서버 환경변수 RESEND_API_KEY 및 WITHU_FROM_EMAIL 설정.
- 운영자 소유의 확인 가능한 테스트 이메일 주소로만 발송 시험을 진행.
- 반환된 제공자 메일 ID를 저장한 뒤 signed webhook의 email.sent, email.delivered, email.bounced, email.failed 이벤트 기록.
- RESEND_WEBHOOK_SIGNING_SECRET을 발급받아 운영 HTTPS 서버 POST /api/webhooks/resend 라우트에 등록.
- email.delivered는 **수신자 메일 서버가 받아들였다는 뜻**이며 실제 받은편지함 배치 또는 사람이 열어본 사실과 다름. 직접 받은편지함과 링크 클릭을 확인해야 한다.
- 해당 메일의 나의 노래함 링크를 열어 주문 번호가 다른 계정의 다른 노래까지 노출되지 않는지 검사.

Resend 공식 자료: https://resend.com/changelog/managing-webhooks-via-api
Svix 웹훅 서명 규격: https://www.svix.com/guides/receiving/receive-webhooks-with-typescript-nodejs/

## Suno 자동 제작과 계약

Suno MCP 공식 소개: https://suno.com/mcp
2026-10 기준 MCP 베타는 개인 Suno 계정과 AI 도구 연결용이며, 이를 다수 소비자 대상 음악 생성 사업용 권리로 간주하면 안 된다.
Suno 공식 사업용 API 사용 승인이 필요하며, 계약상 허용되는 API 인증/생성/결과 보관/음원 라이선스/다운로드 방식이 확정되면 musicProvider.createLicensedSong 인터페이스를 연결한다.
사업용 API가 미연동이면 운영자에게 검증된 주문을 알리고 수동 제작→사운드 검수→비공개 업로드→고객 링크 발송으로 처리한다.

## 운영 관리자 키 위치

모든 실제 키는 서버 Secret Manager/비공개 환경변수에서 관리한다.

| 키 | 역할 |
| --- | --- |
| TOSS_SECRET_KEY / TOSS_CLIENT_KEY | 실 PG 인증(정식 계약 필요) |
| DATABASE_URL | 주문/고객/작업 큐 및 링크 해시 DB |
| OPENAI_API_KEY | 결제 후 서버 작사 |
| RESEND_API_KEY / WITHU_FROM_EMAIL | 거래성 이메일 발송 |
| RESEND_WEBHOOK_SIGNING_SECRET | 메일 도착·반송 webhook 서명 확인 |
| WITHU_OPERATOR_EMAIL / WITHU_OPERATOR_PHONE | 관리자 알림 수신 |
| WITHU_OPERATOR_ALERT_CHANNEL | email, sms 또는 both |
| WITHU_BIZGO_AUTHORIZATION / WITHU_BIZGO_SMS_SENDER | 등록된 문자 발송 API |
| WITHU_PRIVATE_MUSIC_DIR | 공개 저장소 밖 비공개 오디오 보관 경로 |

아직 이메일 본인 인증(OTP), 주문 데이터베이스 및 실제 클라우드 운영 배포가 필요하다. 이메일 링크는 기본적으로 **링크 소유자에게 접근 권한이 있다**. 최초 사용 전 유출·공유될 경우 선점 위험이 있으므로 운영 시 이메일 OTP 또는 인증된 계정 바인딩을 반드시 추가해야 한다.
리셋/회수/환불·정해진 수명·재발급도 운영 DB로 관리한다.
