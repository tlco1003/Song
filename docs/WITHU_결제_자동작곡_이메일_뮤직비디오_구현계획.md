# WITHU — 유료 주문·자동 작곡·이메일·뮤직비디오 구현 계약

작성일: 2026-11-04 | 저장소 `tlco1003/Song` | 고객 브랜드 WITHU

> **중요한 현재 상태:** 고객 주문 화면 UI와 fail-closed 조회 API만 구현돼 있다. 실결제·상업용 자동 작곡·자동 이메일 전송·영상 생성은 **아직 미구현**이며 공개 결제 버튼은 활성화되어 있지 않다. 본 문서는 실행 계약과 아키텍처이며, 외부 업체로부터 사용 승인을 받았다는 뜻이 아니다.

## 목표 고객 경험

1. 사연 다섯 질문 + 상대와의 관계·나이·말투, 장르·분위기를 선택한다.
2. GPT 작사 초안을 검토·수정·확정한다. 편집한 가사·스타일·제목을 최종 산출물로 고정한다.
3. 제품 `audio` (MP3+가사) / `audio_video` (MP3+가사+MP4 뮤직비디오)를 선택하고 수신 이메일을 2회 확인한다.
4. 상품·수량·가격·권리·보관기간·취소·환불 조건을 안내하고, 결제사 공식 결제창에서 인증한다.
5. **결제사 서버 승인 확인과 서버 소유 주문 금액 일치**가 검증돼야만 `paid` 처리한다.
6. 정식 서면 승인된 음악 상업용 B2B API에서 음악을 생성한다. 실패/시간초과의 비동기 재시도 정책을 적용한다.
7. 선택한 경우 사연의 이야기/가사 분석과 생성곡 오디오 타임라인을 기반으로 영상 장면을 생성·조립한다.
8. 원본 MP3/가사/선택 시 MP4를 개인 객체 저장소에 저장한다.
9. 이메일 발송 대행사에서 **다운로드 가능한 만료 링크**를 발송하고 발송 결과를 기록한다.
10. 고객은 주문 추적·재전송·정정·환불·데이터 삭제를 요청할 수 있다.

## 결제 연동

예정 후보: **Toss Payments** 공식 결제창/위젯 API.

공식 개발 가이드:
- https://docs.tosspayments.com/guides/v2/payment-window/integration
- https://docs.tosspayments.com/guides/v2/payment-widget/integration-window
- https://docs.tosspayments.com/guides/v2/get-started/payment-flow

필수 처리:
- 상점 계약 후 공식 **테스트** 키로 샌드박스부터 검증, 라이브 키는 비공개 서버 환경변수에만 보관.
- 상품 ID별 가격은 **서버의 상품 카탈로그**가 원본. 클라이언트가 보낸 금액/할인은 신뢰하지 않는다.
- 랜덤 주문번호/서버 가격/수신인/확정 가사 버전을 주문 DB에 결제 요청 전에 기록한다.
- 모바일에서 공식 Redirect 방식으로 결제 요청, success/fail URL 서버 처리.
- 결제 리다이렉트 파라미터만으로 `paid` 금지. 서버에서 `paymentKey`·`orderId`·`amount` 검증 후 공식 승인 API 호출 및 재조회.
- 중복 콜백과 재시도는 idempotency key·단일 DB 트랜잭션으로 한 번만 승인·제작.
- 결제 완료 즉시 **백그라운드 큐에 작업을 등록하고 사용자에게 상태 표시**. 서버 요청 연결을 수분 동안 붙잡지 않는다.
- **결제 후 음악 생성 실패**를 대비해 재시도 횟수, 고객 통지, 재생성 선택, 전액/부분 환불 정책이 있어야 한다.
- 상업용 음악 생성 계약과 실제 자동 제공/이메일이 검증되기 전에는 **라이브 결제 활성화 금지**.

현재 코드: `docs/checkout.html`, `docs/checkout.js`, `docs/checkout.css`, `src/commerce.mjs` 및 `GET /api/commerce/readiness`.
`POST /api/commerce/orders`는 의도적으로 HTTP 503을 반환하며 **고객 이메일을 저장하지 않는다.** 실제 결제/주문 저장/승인/환불은 아직 연결되지 않았다.

## 음악 API

현재 Suno 소비자 Pro와 개인 MCP는 상용 멀티고객 유료 자동 제작 권한이 아님. 공식 문의 결과 API 신청 폼은 https://sunomusic.typeform.com/apiform 이며, 정식 계약에서 API/Voices 적용 범위를 합의해야 한다.

상업용 B2B API 접근 승인 후 해야 할 일:
1. 계약 가능한 API 범위·인증·크레딧·요금·생성 상태 Webhook/Polling·상업 재판매 권리를 확인한다.
2. `src/providers.mjs`의 **개인용 MCP 프로토타입**과 별도로 정식 B2B provider를 구현한다.
3. 제출할 가사·음악 스타일은 **고객이 최종 승인한 버전만** 사용하고, 성공 응답에 실제 audio asset ID와 수신 가능한 파일 URL이 존재하는지 검증한다.
4. 결과 가사가 원문과 얼마나 일치하는지 점검해 허용 범위를 벗어나면 재생성 또는 고객 승인 절차를 둔다.
5. `paid` 상태 검증 전에는 생성 요청을 보내지 않고, 고객별 원가 및 실패/중복 요청을 기록한다.
6. 보컬 복제는 Voice 소유자 직접 인증과 서버의 허가된 API가 확인된 경우에만 제공한다.

## 이메일 전달

예정 후보: **Resend Email API** https://resend.com/features/email-api

- WITHU가 소유·검증한 발신 도메인을 사용한다. 인증된 발신 주소가 없으면 발송 금지.
- 고객 이메일은 결제·음원 전달 목적으로만 사용, UI와 로그에서 가린다. 결제 자체는 PG가 처리한다.
- 대용량 MP4는 일반 첨부파일보다 **로그인 또는 만료되는 signed download URL**이 적합하다.
- MP3, TXT 가사, MP4의 MIME·파일 크기·보관 기간을 검증한 후 발송한다.
- 이메일의 발송 요청 성공과 실제 전달 성공/반송을 구분하고 중복 발송 방지 키 `orderId+deliveryRevision`를 사용한다.
- 배달 실패 시 재시도·이메일 정정·만료 링크 재발급, 개인정보 삭제 처리 제공.

## 영상 자동 제작 — 가사에 맞춘 장면 전환

예정 후보: Runway 공식 영상 API https://docs.dev.runwayml.com/api/ (이미지→영상 등) 또는 적절한 상업 사용 허가된 대체 API. **아직 실제 사용·승인·생성 결과 검증 없음.**

사용자가 선호하는 영상 예시처럼 **귀엽고 통통 튀는 편집, 10초 안에 4장면 이상 변경**도 가능하게 제품 정의:
- `music_video_short`: 10~15초 수직 영상(하이라이트). 원곡의 특정 후렴을 선택하고, 2~4초 장면 3~5개를 이어 붙인다.
- `music_video_full`: 원곡 길이 전체. 캐릭터·장소·색감을 고정한 여러 장면 및 가사 그래픽을 사용한다. 길이에 비례해 생성 비용/대기 시간 증가.
- `lyrics_visualizer`: 텍스트 애니메이션 + 배경 루프를 활용한 비용 절감형.
- 확정되지 않은 상품에 가격을 임의 지정하지 않는다. 현재 UI의 `audio_video`는 가격·서비스 범위 확정 전 상업적으로 구매 불가.

실행 파이프라인:
1. **원곡 오디오를 먼저 확보**한다(임의 영상 BGM 사용하지 않음).
2. BPM/온셋/강박/구간 에너지 추출, 실제 가사-보컬 강제 정렬(ASR/forced alignment) → `lyricCues` 생성. 한국어 가사 발음·반복 후렴은 사람이 검수할 수 있도록.
3. GPT는 **가사의 사건·감정·인물·장소**를 구분하고 타임라인 `scenePlan`을 작성.
4. 장면별 키 이미지와 동일 캐릭터 참조 자료를 생성·검수, 2~8초 정도로 영상 API 생성.
5. 클립의 영상 원본 오디오는 사용하지 않거나 음소거(제품 의도에 따라), **제작된 노래 오디오를 최종 음악 트랙**으로 사용한다.
6. 장면 연결, 전환, 자막·가사, 파형/비트 마커를 FFmpeg 등으로 타임라인에 맞춰 합성.
7. 출력 MP4 파일 길이·영상 코덱·오디오 일치·싱크 오차를 검사한 후 저장 및 이메일 전달.
8. 원하지 않는 얼굴 변형·인물 음성/초상 사용에는 승인/재생성 절차 둔다.

예시 타임라인(〈세탁소의 신데렐라〉 10초 하이라이트, **실제 오디오 타임코드 확인 전의 연출 설계 예시**):

| 상대 시간 | 화면 | 감정/음악 |
|---|---|---|
| 0.0~2.5초 | 밝은 코인 세탁소, 동전이 데굴데굴 | 통통 튀는 피아노·비브라폰 |
| 2.5~5.0초 | 세탁기 앞에서 양말을 들고 눈을 마주침 | 리듬 악센트, 설렘 |
| 5.0~7.5초 | 빨개진 얼굴, 빨래가 빙글빙글 | 빠른 컷 전환 |
| 7.5~10.0초 | 자정 카운트다운, 양말 한 짝과 미소 | 짧은 극적 마무리 |

**중요:** 이 장면은 가사 내용만을 바탕으로 만든 예시이다. 실제로 맞는 구간의 오디오 시점을 먼저 찾아 확정해야 완전한 싱크가 된다. 영상 AI 한 번 호출로 3~5분짜리 정교한 뮤직비디오가 자동 완성되는 것으로 간주하지 않는다.

제안되는 저장 구조:

```text
Order (private)
  id, productId, confirmedLyricVersion, recipientEmailEncrypted
  providerPaymentId, providerPaymentStatus, amountKrw, currency
  musicProviderJobId, musicAssetId, musicStatus
  videoProviderJobIds[], scenePlan[], videoAssetId, videoStatus
  deliveryStatus, deliveryId, retries, createdAt, retentionUntil
```

상태 전이는 `src/commerce.mjs`의 `ORDER_STATES`를 기준으로 구현하고, 실패·환불·재시도의 계약 검증을 `test/commerce.test.mjs`에서 시작한다.
