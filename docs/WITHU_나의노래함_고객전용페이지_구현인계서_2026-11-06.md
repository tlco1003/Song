# WITHU 나의 노래함: 고객 전용 페이지 연결 지시서

작성일: 2026-11-06

## 1. 실제 화면

- 메인 상단 첫 메뉴에 '나의 노래함'을 노출. 경로는 /my-music.html.
- 같은 메뉴를 제작·상품 선택·결제·공개 곡 상세 화면에도 배치.
- 고객 페이지 /my-music.html은 기존 /song.html의 HTML 플레이어와 동일한 재생 스크립트를 재사용한다.
- 로그인되지 않은 방문자는 빈 노래함 안내와 노래 만들기 링크만 본다. 공개 시범곡을 구매곡처럼 보이지 않게 한다.
- 주문한 곡과 가사가 있는 고객은 서버에서 접근권한이 확인된 뒤에만 음원·가사·곡 목록·반복재생·상업적 이용 옵션을 볼 수 있다.
- 2곡 이상은 나의 완성곡 선택에서 전환. 앞으로 고객 한 명의 여러 주문도 동일한 목록에서 표시하려면 계정별 주문 데이터 연결이 필요하다.

## 2. 상품 페이지 우선순위

- 1곡/2곡/뮤직비디오 선택이 최상단의 핵심 액션이다.
- 장르·장르 혼합·3절 확장·헌정 엔딩과 뮤직비디오 미리보기를 그 다음에 배치.
- 출시 기념 특가세일과 AI 보조·직접 검수 설명은 상품 선택 카드 맨 아래로 이동한다.
- 제작자의 100,000원·200,000원 기준 정상가와 취소선, 실제 판매가 29,000원·39,000원은 상품 카드에 남긴다.

## 3. 이메일 링크에서 나의 노래함까지

1. 실제 PG 승인, 고객 이메일 인증과 제작 완료·선정 파일 검수 통과.
2. 원본을 공개 GitHub 저장소 바깥의 비공개 스토리지에 저장.
3. private-delivery-invitation 모듈이 고객별 난수 토큰과 토큰 SHA-256 해시를 발급.
4. 메일 발송 주소 예시: https://withu.example/my-music.html#delivery=고객별난수토큰
5. 고객이 메일 링크를 열면 song.js가 POST /api/delivery/resolve로 토큰을 검증.
6. 서버가 검증된 주문·인증 고객에만 HttpOnly SameSite 쿠키와 스트리밍용 비공개 주소를 발급.
7. 성공 후 주소에 있던 토큰을 제거하며, 브라우저 내에서는 음악을 감상할 수 있다.
8. 다음 방문부터는 GET /api/delivery/library에서 쿠키 세션을 다시 인증하여 본인 계정의 구매곡 목록을 조회한다.

임의 URL 파라미터, 공개 샘플 파일, 클라이언트 sessionStorage는 실제 주문 인증 근거로 사용하지 않는다.
모든 노래 항목이 인증된 고객과 원주문에 속하는지 서버 어댑터에서 매 요청 시 검증한다.

## 4. 추가 10,000원 상업적 이용과 음원 파일

- 기본 상품은 제작·링크 감상만 포함.
- 구매 후에 표시되는 상업적 이용권 + 원본 음원 파일 10,000원은 별도 결제.
- 원본 주문의 결제와 별도 업그레이드 결제는 서로 다른 PG 주문 ID 및 실제 승인 결과로 검증.
- 상업적 이용권 발급 전에 Suno 출력물의 허용된 공식 다운로드 기록과 제3자 저작권, 원곡·리믹스 제한, 고객에게 라이선스를 부여할 수 있는 권한을 확인.
- 다운로드는 별도로 승인한 최종 곡에 한하며, /api/delivery-downloads/ 아래의 보호 URL만 사용한다.
- 나의 노래함의 곡별 상태는 서버 검증 결과의 commercialUpgrade 필드로 결정한다. 한 주문에서 업그레이드를 받았다고 같은 계정의 다른 미구매 주문까지 열리지 않는다.
- 여러 주문에서 추가 결제할 때는 server-side opaque orderRef로 대상 주문을 선택한다. 서버는 그 orderRef가 실제 해당 세션 소유자인지 다시 검증해야 한다.

## 5. 운영 배포 연동 필요사항

- 운영 HTTPS 도메인에 Node 서버와 고객 전용 HTML을 함께 호스팅하거나 동일 출처 경로로 역프록시.
- 고객 주문 DB와 결제기관 PG 실 승인, 중복 승인·환불·계좌 입금 검증.
- 메일 발송·링크 만료·이메일 인증/재발급.
- 최종 음원/가사 저장소, 로그인 계정과 주문 소유권 연결.
- customerAccess.resolvePrivateDelivery / getPrivateDeliveryLibrary / authorizePrivateAsset / beginCommercialCheckout 구현.
- 파일 응답에 세션 쿠키/재생 요청 범위 확인, 라이선스 다운로드 권한과 결제 검증.
- 실제 iOS/Android에서 백그라운드 재생·쿠키 지속성·만료 처리·다른 주문 접근 차단 검증.

현재 퍼블릭 GitHub Pages는 정적 사이트이므로 **이 파일과 HTML/JS만으로 실결제나 구매 고객 정보가 나타나지는 않는다**.
실제 DB·결제·메일·스토리지 어댑터가 없으면 API는 실패 종료하며 비구매 방문자에게 노래를 표시하지 않는다.
