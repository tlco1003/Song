# WITHU 실제 고객 주문 → 제작 → 이메일 → 개인 노래함 운영 체크리스트
검증 기준 커밋: 8cad6effd1bad19d5ced5eedafa43947ecb264c8 (2026-11-09)

## 1. 고객이 이용하는 정상 흐름
1. `docs/create.html`: 받는 사람·사연·말투·장르·시대를 선택한다. 고객의 비공개 가사·작곡 프롬프트는 브라우저에 노출하지 않는다.
2. `docs/checkout.html`: 1곡·2곡·영상 견적 및 옵션을 선택한다. 상품별 비교 표는 `docs/prices.json`의 유효한 공개 가격을 사용한다.
3. `docs/payment.html`: 운영 Firebase Hosting의 `/api/runtime`에서 실제 결제 가능 상태를 확인한다. 토스 결제 위젯으로 고객이 결제한다. GitHub Pages 정적 사이트에서 실제 PG 결제는 불가능하며 결제를 모방해서는 안 된다.
4. `docs/payment-success.js`: 토스 승인 결과를 `/api/payments/confirm`에 전달한다. 서버는 주문 식별자·실제 결제키·통화·금액·승인 상태를 확인하고 중복 처리를 방지한다. 브라우저의 성공 표시만으로 결제 완료를 인정하지 않는다.
5. `src/production-worker.mjs`: 결제 확인된 주문을 Firestore 트랜잭션으로 선점한다. `src/order-status-portal.mjs`에서 **작사보다 먼저** 접수 안내 메일을 발송한다. 확인용 URL은 `/order-status.html#status=...` 형식이며 비밀 토큰을 서버에서 암호화·해시로 보관한다.
6. 고객은 받은 접수 이메일로 `docs/order-status.html`에 들어와 결제/가사/음악제작/발송 상태를 볼 수 있다. **완성 전에는 음원·다운로드 링크가 나오지 않는다.** 상태 확인 토큰과 음원 다운로드 권한은 별개다.
7. 사업용 음악 생성 제공업체 승인 전에는 `production.status=manual_required`가 정상 동작이다. 운영자는 `docs/admin.html`에서 실제 결제된 주문을 확인하고 곡 수에 맞춰 완성 MP3/M4A/WAV를 각각 업로드한 뒤 가사·장르·권리를 검수한다.
8. 운영자가 **검수 완료된 고객 음원 전송**을 누르면 `src/production-delivery.mjs`가 실제 PG 결제·검수·파일·권리를 재검증한다. 이후 Resend 메일에 `/my-music.html#delivery=...` 전용 감상 링크를 넣는다. Resend의 API 접수는 수신함 도착 확정이 아니므로 웹훅·실제 메일함을 확인한다.
9. 고객은 최종 이메일을 열어 곧바로 `docs/my-music.html`에서 자신의 노래와 가사를 감상한다. 서버는 토큰·세션·주문을 확인하고 파일을 다른 고객에게 제공하지 않는다.
10. 고객은 **무료 공유** QR 카드(PNG), SNS 카드와 가사 인쇄/PDF 저장을 이용할 수 있다. QR에는 공유용 감상 URL만 들어가며 원본 다운로드 권한을 넣지 않는다. 상업적 이용·원본 다운로드는 별도의 결제와 라이선스 검증이 있을 때만 가능하다.

## 2. 관리자 확인 경로
- **실제 주문함:** `/admin.html` — Firebase 인증된 운영자 UID 외에는 거부
- **주문 접수 이메일 재시도:** 해당 주문 선택 → `주문 접수 이메일 보내기 · 재시도`
- **상태 화면:** `/order-status.html#status=주문별토큰` — 구매자에게 보낸 접수 이메일로만 토큰 전달
- **최종 감상:** `/my-music.html#delivery=주문별토큰` — 최종 검수 완료 이메일로만 전달
- **집계:** 운영자 전용 `/api/admin/analytics` 및 관리자 7일간 유입·전환 집계. 방문/클릭은 중복될 수 있으며 결제 성공 지표는 PG 검증 성공 레코드로만 기록
- **이메일 발송사:** `src/withu-notification-providers.mjs`; 운영 계약 계정으로 Resend 전송. 고객 주소, 원문 사연, 토큰을 외부 분석 코드나 공개 로그에 기록하지 않기

## 3. 운영 환경에서 제공해야 할 것
소스코드를 커밋했다고 운영 서비스가 켜지는 것은 아니다.

**필수 외부 준비**
- Firebase 프로젝트·Hosting·Functions(asia-northeast3), Firestore·Storage 및 배포/요금 설정
- 등록/승인된 Toss Payments 상점 및 테스트/실결제 키
- Resend 계정의 검증된 발신 도메인·발신 이메일, Resend 웹훅 설정
- Firebase Authentication의 운영자 계정 UID와 이메일 인증
- OpenAI 작사용 API 계정/과금 및 별도 서버 비밀 키
- 사용자 맞춤곡의 판매·고객 전달·상업적 이용에 대한 권리 검토 및 Suno **별도 B2B/API 서면 승인** (없다면 안전한 운영자 수동 제작 모드 유지)

**환경 변수**
`functions/.env.example`에 **비밀이 아닌** 설정명이 정리되어 있다. 실값은 GitHub 커밋 금지.
`WITHU_PUBLIC_BASE_URL`은 `https://운영-Firebase-Hosting-도메인/` 형태의 같은 출처 루트여야 한다. `WITHU_PAYMENT_MODE=test`에서 먼저 검증하고 상용 승인 전에는 `WITHU_LIVE_PAYMENTS_ENABLED=false`를 유지한다.

Firebase Secrets: `TOSS_SECRET_KEY`, `RESEND_API_KEY`, `WITHU_LINK_ENCRYPTION_KEY`(64자리 hex), `RESEND_WEBHOOK_SIGNING_SECRET`, `OPENAI_API_KEY`. 인증키·이메일 토큰·가사·고객 사진을 GitHub Pages/공개 저장소에 저장하지 않는다.

**검사와 배포**
```sh
npm run check
npm test
npm run firebase:prepare
# Firebase 프로젝트를 운영자 계정으로 선택하고 권한·Secrets·계약을 검증한 후
npm run deploy:firebase
```
`npm run firebase:prepare`는 `src/*.mjs`를 `functions/src/`로 복사한다. `firebase deploy`는 운영자만 실행해야 한다. 이 문서의 작성은 실제 Firebase 배포나 Toss·Resend 연결 성공을 뜻하지 않는다.

## 4. 운영 수락 시험 (실서비스에서 직접)
- 시연/테스트 PG로 **실제 테스트 주문 한 건**을 생성하고 결제 금액·환불/취소 경로 확인
- 결제 승인 → 접수 안내 메일이 들어오는지, 링크가 자기 주문의 진행 상황만 표시하는지 확인
- 같은 결제키 재호출·중복 알림에서도 주문 수, 결제/접수 메일, 다운로드 권한이 중복 부여되지 않는지 확인
- 다른 고객 토큰, 존재하지 않는 토큰, 만료/회수 토큰, 다른 출처 요청은 실패해야 함
- 고객 감상 페이지에서 원본 파일이 공개 URL로 노출되지 않고, 추가 결제 없이 다운로드할 수 없는지 확인
- 관리자 최종 MP3 업로드, 가사·권리 검수 후 **고객 완료 이메일을 발송**하고 모바일 Safari/Chrome에서 실제 감상 재생
- QR 선물 카드 스캔으로 공유 감상만 가능하고 파일 다운로드는 불가능한지 확인
- 브라우저 인쇄에서 가사가 PDF로 저장되는지 확인
- 관리자가 주문 접수/완료 메일과 7일 집계를 볼 수 있는지 확인
- AI 작사/Resend 중단 시 가짜 성공 처리를 하지 않고 관리자가 재시도할 수 있는지 확인

## 5. 아직 상용 운영 완료라고 주장할 수 없는 항목
- 공개 `tlco1003.github.io/Song/`은 정적 호스팅: `/api/**`의 Firebase Cloud Functions가 없다. 이 주소만으로 실제 결제·접수 이메일·권한 있는 고객 감상을 할 수 없다.
- Suno 소비자용 MCP 연결은 유료 고객 대상 B2B 자동 작곡 허가를 대신하지 않는다. 승인되기 전 음악 제작 자동화는 **차단**, 운영자 수동 제작.
- QR은 링크 카드로 렌더하고, PDF는 브라우저의 **인쇄 → PDF로 저장** 기능이다. PDF 전용 서버 생성은 구현하지 않았다.
- 시대/장르 근거 JSON은 별도의 **검증된 원출처 실제 데이터**를 비공개 `WITHU_PRIVATE_STYLE_DIR/evidence`에 넣어야 한다. 현재는 검증 스키마·엔진 연결만 구현되어 있다.
- GitHub Actions의 테스트 통과는 실제 토스 결제 승인, Resend 수신함 전달, 외부 시스템 배포 또는 상업 라이선스 계약 성공을 의미하지 않는다.
