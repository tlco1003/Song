# WITHU 공개 예시곡 가사 타임코드 운영 안내

## 원인과 원칙

기존 플레이어는 곡 전체 재생시간을 가사 줄 수로 나눠 다음 줄을 표시했다. 이는 실제 노래의 전주·간주·반복·늘임음을 측정하지 않으므로 **정확한 가사 싱크가 아니다.**

개선한 재생기는 다음 계약을 따른다.

1. 기존 일반 가사 TXT에 줄별 시간 정보가 없으면 **곡 길이로 자동 이동을 추정하지 않는다.** 사용자는 메인 가사를 직접 스크롤할 수 있다.
2. 각 줄에 **실제 시작 시각**이 있는 TXT에서만 플레이어의 `currentTime`을 읽어 해당 구절을 강조하고 스크롤한다. 일시정지·탐색·배속에도 재생 시간 기준으로 동작한다.
3. 시간은 분:초.소수 둘째자리로 적는다. 예시 `[00:17.25]첫 번째 가사`는 **형식 설명을 위한 임의 시각**이며 현재 공개곡을 분석하여 검증한 값이 아니다.
4. 가사 줄 모두에 시각이 있어야 하며 시각은 엄격히 증가해야 한다. 일부 누락, 중복, 역순이면 자동 이동을 하지 않는다.
5. 단순히 파일명만 바꾸거나 가사를 길이 비례로 나누어 시간 정보를 만들어서는 안 된다.
6. 공용 음악 샘플에만 적용한다. 실제 구매자 개인 노래/음성/가사는 공개 `docs/media`에 올리지 않는다.

## 기존 곡별 편집 절차

1. 공개 예시곡 싱크 작업실인 `docs/lyric-timer.html`을 연다. GitHub Pages 기준: `https://tlco1003.github.io/Song/lyric-timer.html`
2. 곡을 선택하고 실제 음악을 재생한다.
3. 각 가사가 **실제로 시작하는 순간** 「현재 구절 시작 시각 기록」을 누르거나 해당 줄에서 「지금 기록」을 누른다. PC에서는 스페이스바도 사용 가능하다.
4. 잘못된 구간은 줄별 초 입력이나 `±0.1초` 조정으로 수정한다. 모든 줄 기록 후 시간이 계속 증가하는지 검토한다.
5. 「시간 맞춘 가사 TXT 다운로드」로 **같은 이름의** `lyrics-....txt`를 저장한다.
6. GitHub `docs/media/`의 동일한 TXT 파일을 업로드된 파일 내용으로 교체한 뒤 병합/배포한다. `tracks.json` 수정은 필요 없다.
7. 실제 재생에서 도입부, 긴 간주, 후렴 반복, 재생 위치 드래그, 모바일 세로 화면, 다른 곡 전환을 확인한다.

편집값은 기기의 `localStorage`에 임시 저장된다. 작업실에서 다운로드만 하면 사이트가 바뀌지 않으며, GitHub에서 TXT 파일을 교체해야 실제 고객 메인화면이 업데이트된다.

## 검증 기준

- 전주: 첫 가사 시작 시각 전에는 활성 가사를 표시하지 않는다.
- 본문: 라인이 시작되는 시각이 도래한 뒤에만 강조한다.
- 간주: 다음 가사 구절이 실제 시작하기 전에는 미리 넘기지 않는다.
- 탐색: 재생바를 임의 위치로 옮기면 해당 위치의 타임코드 줄을 표시한다.
- 가사 없는 곡/시간 미등록 곡: 멋대로 자동 스크롤하지 않는다.
- 유효하지 않은 TXT: 부분 타임코드를 자동 싱크로 간주하지 않는다.
- 영상과 음악: 무음 반복 장식 영상이 아니라 **음성이 포함된 실제 재생기**의 `currentTime`으로 맞춘다.

**현재 GitHub 가사 파일 8개에 실제 타임코드는 아직 없다.** 실제 녹음을 들어 시각을 기록해야 정확히 동기화된다. 시간표를 생성하지 않은 곡을 '정확한 자동 싱크 완료'라고 표시하지 않는다.

## 전체 10곡 자동 분석 초안 작업 (2026-11-06)

- GitHub Actions의 `Draft lyric synchronization` 실행은 공개된 `docs/media/tracks.json`의 **모든 곡**을 읽어 음원 + 공식 가사로 타임코드 **초안**을 작성한다.
- 실행은 `lyric-align 0.4.2`의 `faster-whisper` 한국어 음성인식 기반이다. 노래를 사람 말처럼 완전히 듣지 못할 수 있고, 후렴 반복이나 잔잔한 발라드에 시점 오류가 생길 수 있다. 초안을 사실로 인정하지 않는다.
- 자동 분석은 `scripts/draft-lyric-sync.py`에서 수행하며 결과는 Actions artifact `public-lyric-sync-drafts`에서 내려받을 수 있다.
- 결과는 각 곡마다 `song-*.json`과 `report.json`이다. `matched: false` 또는 비정상적인 시간 정보는 **null** 로 보존하고 절대로 길이 비례로 채우지 않는다.
- `lyric-timer.html`에서 곡을 선택하고 동일한 곡 ID의 JSON을 **싱크 초안 불러오기**로 가져온다. 인식된 부분부터 재생해 다시 듣고, 잘못된 후렴/도입/간주와 빈 줄을 교정한다.
- 모두 확인한 뒤 원본 `lyrics-....txt`와 동일한 파일명으로 **시간 맞춘 가사 TXT**를 다운로드하고, 검토한 파일만 GitHub `docs/media`에 게시한다. 본 사이트는 고객의 비공개 음원에 이 작업을 수행하지 않는다.
- 음원 전체나 결제 데이터, Suno 개인 토큰을 외부 API로 전송하지 않는다. 음원 및 코드만 GitHub Actions 러너에서 처리하고 외부에 보낼 타임코드 초안은 아티팩트로 저장한다. 단, 오픈소스 ASR 모델 다운로드에는 외부 네트워크를 사용한다.
- 게시된 가사의 실측 검수 없이는 '10곡 가사 싱크 완료'라고 주장하지 않는다. 자동 분석 결과만으로 고객에게 정확한 가사 싱크를 제공해서는 안 된다.
